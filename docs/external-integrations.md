# Внешние интеграции

Эмулятор предназначен только для разработки: состояние хранится в памяти и
теряется при перезапуске; операции не являются реальными платежами. Это отдельный
процесс, а не часть Rental API.

```bash
docker compose up --build external-services
pipenv run python -m pytest tests/integrations
```

HTTP-контракты доступны по `http://localhost:3629/docs`. Станция
`empty-station-id` не содержит пауэрбанков. `PUT /admin/failures/{service}` с
`{"mode":"error"}`, `{"mode":"timeout"}` или `{"mode":"none"}` включает и
выключает сбои для `stations`, `payments`, `tariffs`, `users`, `configs`.
Для `stations` и `payments` режимы `error_after` и `timeout_after` имитируют
потерю ответа после выполнения операции: после отключения сбоя тот же ключ
вернёт исходный результат, не выполнив операцию повторно.
Таймаут задаётся `EMULATOR_TIMEOUT_SECONDS`. `POST /admin/return-events`
отправляет callback в URL `RENTAL_CALLBACK_URL`; повтор того же события с теми
же данными повторно отправляет callback. Идентификатор события — UUID.
Отправка события не меняет инвентарь эмулятора. Результат callback нельзя проверить,
пока Rental API с соответствующим маршрутом не запущен.

`app.integrations.http` предоставляет HTTP-адаптеры портов. Они получают общий
`httpx.AsyncClient` и базовый URL; владелец клиента закрывает его. Timeout каждого
адаптера задаётся в `.env.example` (переменные среды необходимо загрузить при
запуске). По умолчанию один повтор выполняется при сетевой ошибке, timeout,
429 или 5xx; POST-команды повторяются только с обязательным неизменным ключом
операции. `ExternalServiceUnavailable` означает технический сбой или неизвестный
результат, `ExternalServiceError` — в том числе 4xx или невалидный контракт
для чтения. `ExternalOperationUnknown` означает, что результат команды платежа или
выдачи неизвестен (в том числе при невалидном ответе). Повторять команду нужно
с тем же ключом; жизненный цикл должен обработать этот исход отдельно от отказа.

`CachedConfigClient.start()` должен успешно выполниться до readiness; затем он
обновляет конфигурацию раз в минуту и сохраняет последнее значение при сбое.
При завершении приложения нужно вызвать `close()`. `CachedTariffClient` принимает
этот клиент, ограничивает TTL диапазоном 1–600 секунд и размер LRU; устаревший
тариф не возвращается при недоступном источнике. `FallbackUserClient` оборачивает
HTTP-клиент и при технической недоступности возвращает профиль без подписки и
доверенности. Таким образом бизнес-логика должна применять базовый тариф и
`default_deposit`. В лог передаётся событие `user_fallback` через поля записи;
Ошибки интеграций также записываются с полями события, сервиса и метода;
JSON-форматирование логов настраивается приложением.

Пример подключения (создание объектов должно выполняться в жизненном цикле API):

```python
http = httpx.AsyncClient()
configs = CachedConfigClient(HTTPConfigClient(http, base_url))
await configs.start()
tariffs = CachedTariffClient(HTTPTariffClient(http, base_url), configs)
users = FallbackUserClient(HTTPUserClient(http, base_url))
# при остановке: await configs.close(); await http.aclose()
```

Настройки хранения по странам доступны через `retention_days_by_country` в
`AppConfig`; отсутствие страны означает использование бизнес-логикой значения
по умолчанию. Фактическое подключение адаптеров, readiness и callback к Rental API
остаётся за интеграцией с остальными участниками. Защиту callback, постоянное
хранение состояния эмулятора и продуктивный платёжный протокол эта заглушка не
реализует.

Эмулятор возвращает результат платёжной команды и обеспечивает идемпотентность
по её ключу. Порядок и состояние платёжных операций здесь не моделируются.
